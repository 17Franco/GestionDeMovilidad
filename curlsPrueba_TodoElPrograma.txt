PRUEBAS MANUALES - TODO EL PROGRAMA GESTION DE MOVILIDAD
=========================================================

Este documento combina las pruebas de:
- curlsPrueba.txt
- curlsPrueba_Grafana_InfluxDB.txt
- curlsPrueba_Messaging_JMS.txt

Esta pensado para probar el programa por funcionalidades, en orden.
No hace falta pegar todo de una sola vez: conviene ejecutar por secciones.

Requisitos generales:
- La aplicacion GestionDeMovilidad debe estar desplegada en WildFly.
- MariaDB/MySQL debe estar levantado.
- La queue JMS reclamosQueue debe estar configurada con config.cli.
- Los usuarios de prueba usan la contrasena: 1234.
- Si la base no esta limpia, los IDs de estaciones/cargadores pueden cambiar.

Puertos usados:
- Aplicacion: http://localhost:8080/GestionDeMovilidad
- Grafana: http://localhost:3003/
- InfluxDB: localhost:8086
- Ollama: http://localhost:11434


0. INSTALACION INICIAL DE CONTENEDORES DOCKER
---------------------------------------------

Ejecutar esta seccion solo la primera vez, si los contenedores no existen.
Si ya existen, saltar al punto 1.

Ver contenedores existentes:
docker ps -a

Crear contenedor de InfluxDB + Grafana:
docker run -d --name docker-influxdb-grafana -p 3003:3003 -p 8086:8086 -p 3004:8083 philhawthorne/docker-influxdb-grafana:latest

Crear contenedor de Ollama:
docker run -d --name ollama -p 11434:11434 ollama/ollama

Descargar el modelo usado por ClasificadorReclamosImpl:
docker exec ollama ollama pull qwen2.5:0.5b

Verificar que los contenedores existen:
docker ps -a


1. LEVANTAR CONTENEDORES PARA METRICAS, GRAFANA Y OLLAMA

11. PROBAR DEUDA Y PAGAR DEUDA
------------------------------

Esta seccion prueba que un cliente con deuda no pueda iniciar una carga nueva,
y que luego pueda pagar esa deuda.

IMPORTANTE SOBRE LOS ENDPOINTS:
- En el codigo actual el endpoint activo esta en /movilidad/cargas/pagarDeuda.
- El endpoint viejo /movilidad/pagos/pagarDeuda aparece en documentos anteriores,
  pero en ApiModuloPago el endpoint de pagos directos esta comentado.

Ana inicia una carga con la tarjeta que el mock trata como rechazada:
curl -i -u "1111111-1:1234" -X POST -H "Content-Type: application/json" -d '{"cargadorID":1,"metodoPago":"TARJETA","numeroTarjeta":"22222222"}' http://localhost:8080/GestionDeMovilidad/movilidad/cargas/iniciar

Ana finaliza la carga.
Si el mock rechaza la tarjeta, debe responder que el pago fue rechazado y quedo deuda pendiente:
curl -i -u "1111111-1:1234" -X POST http://localhost:8080/GestionDeMovilidad/movilidad/cargas/finalizarCargaActual

Ana intenta iniciar otra carga.
Debe responder 400 porque tiene una deuda pendiente:
curl -i -u "1111111-1:1234" -X POST -H "Content-Type: application/json" -d '{"cargadorID":1,"metodoPago":"CUENTA_UTE"}' http://localhost:8080/GestionDeMovilidad/movilidad/cargas/iniciar

Ana intenta pagar la deuda desde el endpoint actual del modulo carga:
curl -i -u "1111111-1:1234" -X POST http://localhost:8080/GestionDeMovilidad/movilidad/cargas/pagarDeuda

Nota:
El endpoint actual no recibe numeroTarjeta en el JSON; usa el medio de pago
asociado a la carga con deuda. Si el mock vuelve a rechazar esa misma tarjeta,
puede responder 402 y la deuda va a seguir pendiente.

Ana vuelve a intentar iniciar una carga.
Si la deuda se pago correctamente, debe responder 201:
curl -i -u "1111111-1:1234" -X POST -H "Content-Type: application/json" -d '{"cargadorID":1,"metodoPago":"CUENTA_UTE"}' http://localhost:8080/GestionDeMovilidad/movilidad/cargas/iniciar

Si tu version tiene habilitado el endpoint viejo del modulo pagos, el comando era este:
curl -i -u "1111111-1:1234" -X POST -H "Content-Type: application/json" -d '{"numeroTarjeta":"11111111","monto":500}' http://localhost:8080/GestionDeMovilidad/movilidad/pagos/pagarDeuda

15. CONSULTAS RECOMENDADAS PARA GRAFANA
---------------------------------------

Entrar a Grafana:
http://localhost:3003/

Usuario:
root

Contrasena:
root

Panel tipo Time series - Cargas Activas en el Tiempo:
SELECT last("value") FROM "cargasActivas" WHERE ("metric_type" = 'gauge') AND $timeFilter GROUP BY time($__interval) fill(previous)

Panel tipo Stat o Gauge - Cargas Activas Actuales:
SELECT last("value") FROM "cargasActivas" WHERE ("metric_type" = 'gauge') AND $timeFilter

Panel tipo Stat - Total Pagos con Tarjeta:
SELECT sum("value") FROM "pagosConTarjeta" WHERE $timeFilter

Panel tipo Time series - Pagos con Tarjeta en el Tiempo:
SELECT sum("value") FROM "pagosConTarjeta" WHERE $timeFilter GROUP BY time($__interval) fill(0)

Panel tipo Stat - Total Reclamos Negativos:
SELECT sum("value") FROM "reclamosNegativos" WHERE $timeFilter

Panel tipo Time series - Reclamos Negativos en el Tiempo:
SELECT sum("value") FROM "reclamosNegativos" WHERE $timeFilter GROUP BY time($__interval) fill(0)

Notas:
- Para cargasActivas usar last(value), porque es un Gauge.
- Para pagosConTarjeta y reclamosNegativos usar sum(value), porque son Counters.
- Para que "Cargas Activas en el Tiempo" muestre cambios, primero hay que iniciar cargas, esperar 12 segundos, y despues finalizarlas.


16. INVENTARIO COMPLETO DE ENDPOINTS DETECTADOS
-----------------------------------------------

Base URL:
http://localhost:8080/GestionDeMovilidad/movilidad

Modulo Cliente:

POST /clientes
Registra un cliente.
Ejemplo usado en seccion 3.

POST /clientes/reclamos
Registra un reclamo del cliente autenticado.
Ejemplo usado en seccion 12.

GET /clientes/obtener
Lista clientes, pero actualmente comparte el mismo path con mostrarReclamos().
Ejemplo:
curl -i -u "1111111-1:1234" http://localhost:8080/GestionDeMovilidad/movilidad/clientes/obtener

POST /clientes/medioPago
Registra una Cuenta UTE o Tarjeta para el cliente autenticado.
Ejemplo usado en seccion 4.

Modulo Carga:

POST /carga/estacion
Crea una estacion.
Ejemplo usado en seccion 5.

POST /carga/cargador
Crea un cargador asociado a una estacion.
Ejemplo usado en seccion 6.

POST /cargas/iniciar
Inicia una carga para el cliente autenticado.
Ejemplo usado en secciones 8, 10 y 11.

GET /cargas/verCarga
Obtiene la carga actual del cliente autenticado.
Ejemplo usado en secciones 7 y 9.

GET /cargas/verHistorial
Obtiene el historial de cargas del cliente autenticado.
Ejemplo usado en secciones 9 y 10.

POST /cargas/finalizarCargaActual
Finaliza la carga actual y dispara el pago.
Ejemplo usado en secciones 10 y 11.

POST /cargas/pagarDeuda
Intenta pagar la deuda pendiente del cliente autenticado.
Ejemplo usado en seccion 11.

Modulo Pago:

GET /pagos
Consulta pagos por cliente y rango de fechas, pero actualmente los parametros
del metodo no tienen @QueryParam.
Ejemplo propuesto:
curl -i "http://localhost:8080/GestionDeMovilidad/movilidad/pagos?ci=1111111-1&fechaIni=2026-01-01&fechaFin=2026-12-31"

POST /pagos/pagarConTarjeta
Aparece anotado en ApiModuloPago, pero esta dentro de un bloque comentado.
No deberia considerarse disponible en la version actual.

Endpoints repetidos o dudosos detectados:
- GET /clientes/obtener esta duplicado en ModuloClienteApi.
- GET /pagos necesita @QueryParam para que los parametros de query funcionen.
- POST /pagos/pagarConTarjeta y el endpoint viejo /pagos/pagarDeuda pertenecen
  a pruebas/documentos anteriores, pero no estan activos en el codigo actual.


17. DIAGNOSTICO RAPIDO
----------------------

Si Grafana muestra "No data":
- Verificar que docker-influxdb-grafana este Up: docker ps
- Esperar al menos 12 segundos despues de ejecutar curls.
- Revisar InfluxDB con SHOW MEASUREMENTS.
- Revisar que el rango de tiempo de Grafana incluya el momento de la prueba.

Si cargasActivas muestra numeros enormes:
- Revisar que no se este usando SELECT SUM(value) FROM cargasActivas.
- Usar SELECT LAST(value) FROM cargasActivas.

Si reclamosNegativos no aparece:
- Verificar que se envio un reclamo negativo.
- Verificar que Ollama responde: curl http://localhost:11434/api/tags
- Verificar actividad en la queue JMS con messages-added.

Si message-count queda en 0:
- Puede estar bien. Con consumer activo, los mensajes entran y salen rapido.
- Para ver actividad mirar messages-added.

Si aparece error de conexion con Ollama:
- Iniciar el contenedor: docker start ollama
- Verificar el puerto 11434: curl http://localhost:11434/api/tags
